# 数据分析 Tool 设计

> 版本：v2.1 · 2026-11-16
> v2.1：新增平台资源 / 项目授权管理（resource_service）与运行时 tool/skill 过滤
> 相关代码：`ai_service/tools/`, `ai_service/agent/tools/`, `resource_service/`

---

## 核心设计原则

**只做生成不做执行** — Tool 层负责读取元数据和采样，Skill 层负责指导模型生成分析代码。

**架构分层**：
- Tool 是 LLM 的入口，负责参数校验、调用 Manager、格式化结果
- Manager 是实际干活的（PostgreSQL 只读查询、CSV 文件读取、统计计算）
- 执行型 Agent（data_explore / csv_explore / leader）通过 function-calling 使用工具

---

## 注册机制

`ToolRegistry` 在系统启动时**扫描 tools/ 目录，自动注册所有继承 `BaseTool(ABC)` 的类**

### 工具白名单（config.json 控制）

每个 agent 的 `tools` 白名单决定它能用哪些工具。leader 默认全量可用；子智能体按职责裁剪。

### 可配置排除

config.json 的 `tools.excluded` 可配置排除特定工具名，注册时即过滤掉。

## 平台资源与项目授权（resource_service）

管理面与运行面共用一套可用性口径，DB 存于 PostgreSQL `agent` schema（init/params_schema.sql + init/pg_seed.sql）：

| 表 | 层级 | 说明 |
|---|---|---|
| `agent.tool` / `agent.skill` | 平台全局 | 资源元数据 + `is_platform_enabled` 总开关（紧急熔断）+ 备注 |
| `agent.app_tool` / `agent.app_skill` | 项目授权 | owner 在平台已开放范围内开关本 App 授权、覆写工具配置（override_config） |
| `agent.agent` | 平台全局 | 智能体手动启停（见《多Agent设计.md》§2） |

**可用性规则**（tool/skill 相同）：

- 实际可用 = `is_platform_enabled` ∧ 项目授权；项目未单独配置时**默认继承平台状态**（平台开放即默认授权），无需预置 `app_tool/app_skill` 行；
- 平台总开关为平台级紧急熔断：关闭后所有 App 不可用，owner 侧开关禁用；
- 平台已下线的资源禁止在项目侧重新开启（后端拦截）；
- 建项目时 `init_app_resources(app_id)` 复制一份当前平台已开放资源作为初始授权。

**运行时接入点**（每轮实时查库，改开关下一轮对话即生效）：

- 工具：`BaseReActAgent._resolve_tool_catalog` 取 `get_disabled_tool_codes(app_id)` → `ToolRegistry.build_tools(allowlist, disabled)` 先剔除禁用、再按 config 白名单裁剪；
- 技能：`_prepare_prompt_params` 取 `get_disabled_skill_codes(app_id)` → `skill_loader.build_prompt(disabled=...)` 不渲染被禁用技能；
- 查库失败返回 `None`，调用方 **fail open**（不做额外过滤），避免配置表未初始化时把功能全部切断。

管理接口：`/params/tool/*`、`/params/skill/*`（管理员），`/params/app/grant/*`（owner/admin，含 owner 鉴权）；前端为「平台资源」（管理员）与「应用授权」（owner）两个页面。

## Manager 设计

### PostgresManager（data_explore 实际使用）

- **数据库连接管理**：从应用配置获取连接信息
- **只读查询**：禁止写操作（INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE）
- **SQL 注入防护**：参数化查询
- **大表保护**：统计类查询加 `MAX_EXECUTION_TIME` hint；所有聚合查询默认加 LIMIT

### CsvManager

- **文件安全**：限定在配置的 `data_dir` 安全路径内，路径越界拒绝
- **自动编码检测**（chardet）
- **大文件保护**：> 500MB 强制采样（按文件大小比例跳过随机偏移后顺序读块）
- **行数估算**：大文件用文件大小 ÷ 前 1000 行平均行长估算

### StatsEngine（统计计算公共逻辑）

- `compute_numeric_stats`：均值/方差/分位数（支持采样模式）
- `compute_categorical_stats`：频率统计，去重超 max_distinct 截断
- `compute_correlation`：相关性矩阵，数值列超限时取前 N 列
- **统一采样策略**：< 10万全量 → 10-50万 10% → 50-200万 5% → > 200万 1%；采样结果标 `~` 前缀 + `≈估算值`

## 大表 / 宽表处理策略

### CSV 大文件应对

| 场景 | 判定 | 触发动作 |
|---|---|---|
| 大文件 | > 50MB 或行数 > 50万 | 自动降级采样（50万→30%, 200万→10%） |
| 宽表 | 列数 > 50 | 自动剪裁到 30 列（数值→时间→低基数优先） |
| 超大文件 | > 500MB | 强制采样（500MB→20%, 1GB→10%, >2GB→5%） |

降级时在返回结果首行标注：
```
[采样率 10%，全量约 2300 万行] [已跳过 17 列: col_a, col_b, ...]
```

### PostgreSQL 查询应对

| 场景 | 处理 |
|---|---|
| 大表行数 | 统计查询自动加 LIMIT + MAX_EXECUTION_TIME |
| 时间范围 | 必须明确起止日期占位符 |
| 聚合安全 | 除零保护（NULLIF / COALESCE） |

## 关键设计约定

1. **工具是只读入口** — 数据探索工具只查询、不修改；写操作由文件操作工具（write_file / edit_file）完成
2. **结果截断** — ToolExecutor 统一 `MAX_TOOL_RESULT_CHARS=8000` 截断，避免大表撑爆上下文
3. **参数校验前置** — BaseTool.validate_params 在 execute 之前校验必填参数
4. **Hook 守卫** — 许可规则链（tool_permission_guard）+ 文件参数（file_tool_param_guard）+ 审批（hitl_approval_guard）在 BEFORE_TOOL_CALL 拦截
5. **dispatched 不继承 BaseTool** — dispatch_agent 虽然叫"工具"，其实是特殊的 agent-as-tool 执行器，继承 BaseTool 但内部走特殊路径

## 工具执行


### 单工具执行流程

```
ToolExecutor.execute(tool_call)
  ├─ 注入 session_id（inject_tool_context）
  ├─ BEFORE_TOOL_CALL 守卫（文件参数 / 许可规则链 / HITL 审批）
  │    ├─ blocked → 失败 ToolResult（error_class 由守卫标注）+ END(FAILED) 事件
  │    └─ patches.tool_arguments → 合并改写后的参数再执行
  ├─ 工具存在性兜底 → 不存在则 END(FAILED) 事件
  ├─ 熔断准入 acquire_slot → 熔断打开则 END(FAILED) 事件
  ├─ ★ TOOL_EXECUTION_START 事件（前端实时感知"正在执行什么工具"）
  ├─ 执行 executor（可声明 signal / session_state，按签名注入）+ trace span
  ├─ AFTER_TOOL_CALL 钩子（语义落表 / 落盘 / 记忆信号）
  ├─ 熔断记账 record_outcome + 工具指标打点
  └─ ★ TOOL_EXECUTION_END 事件（成功 / 失败）→ 返回 ToolResult
```


### 并行执行

调度入口 `dispatch_tool_calls` 按 `config.tools.execution_mode` 分流：

| 模式 | 调度器 | 行为 |
|---|---|---|
| `parallel`（默认） | `execute_parallel` | 全部工具 `asyncio.gather` 并发执行 |
| `sequential` | `execute_sequence` | 按 tool_calls 顺序串行执行（开关保留，便于排障/降级） |

两版共用三个 helper：归一化（参数 JSON 字符串兜底解析）、同批去重、结果回填组装。

```
LLM 输出 tool_calls
  │
  ▼
dispatch_tool_calls（按 execution_mode 分流）
  ├─ 归一化：(name, arguments, tool_call_id, 去重 key)
  │    去重 key = name + 参数序列化后剔除全部空白（仅空白差异视为同一调用）
  ├─ 两级进程级信号量限流（见下）
  ├─ 并发执行 execute()（单工具：守卫 → 熔断准入 → 执行 → 记账 → AFTER）
  └─ 按原 tool_calls 顺序回填 tool 消息（完成顺序 ≠ 回填顺序）
```

**两级信号量（防嵌套死锁）**

| 信号量 | 配置项 | 覆盖范围 |
|---|---|---|
| `agent_slots` | `multi_agents.max_parallel` | 仅 `dispatch_agent` |
| `tool_slots` | `tools.max_concurrency` | 其余全部工具（含子 agent 内部工具） |

- 信号量为**进程级**（执行器实例属性），不是 per-turn，限的是全局并发资源；
- `dispatch_agent` **只占 agent_slots、不占 tool_slots**：否则同轮多个派发会吃光工具席位，子 agent 内部工具等不到席位 → 嵌套死锁；
- 子 agent 不能再派发子 agent，嵌套深度恒为 1，两级信号量无环。

**并发安全约束**

- 同批去重缓存在并行版用 `dict[key, asyncio.Task]`（首见创建 task、后来者 await 同一个 task），避免并发下相同调用重复执行；
- `activate_turn.tool_call_counts` 累加是无 await 的同步段，asyncio 单线程下并行安全；
- 停止信号 `TurnStoppedError` / `CancelledError` 经 gather 透传终止整轮；普通异常收口为 `ToolResult(success=False)`，不波及兄弟工具。

### hook 拦截

守卫全部注册为 `BEFORE_TOOL_CALL` 监听器，执行器只负责执行与记账：

| 守卫 | 优先级 | 职责 |
|---|---|---|
| `file_tool_param_guard` | 低 | 文件类工具参数/路径规范化 |
| `tool_permission_guard` | 10 | 规则链：存在性 → 次数配额 → 路径安全 → 熔断可用性，deny 即阻断 |
| `hitl_approval_guard` | 50 | 高风险调用挂起等人工审批；拒绝则阻断，审批人改写参数经 `patches.tool_arguments` 合并后执行 |

阻断时 `ctx.data["error_class"]` 标注指标口径，`ctx.message` 原样回填为 tool result 让 LLM 改路。

### 工具执行失败的处理

按"失败不吞、不炸整轮"原则统一收口：

| 失败类型 | 处理 | error_class |
|---|---|---|
| 守卫阻断（参数/权限/审批/配额/熔断可用性） | 不执行，阻断原因回填为 tool result | 守卫标注（如 `arg_invalid` / `quota_exceeded`） |
| 工具不存在 | 不执行，返回可用工具清单引导重发 | `arg_invalid` |
| 熔断打开 | 快速失败，提示稍后重试或换工具 | `circuit_open` |
| 执行异常 | 捕获并转 `ToolResult(success=False, message="异常类型: 说明")` | `execution` / `timeout` |
| 子 agent 业务失败 | `dispatch_agent` 返回"执行失败：原因" | `subagent_failed` |
| 停止信号 | 不转失败，`TurnStoppedError` 向上传播终止整轮 | — |

回填给 LLM 的内容：成功传 `data`，失败优先传 `message`；超过 `MAX_TOOL_RESULT_CHARS=8000` 截断并标注原长。

### 熔断

- 每个工具名独立一个三态熔断器（closed / half_open / open），进程内共享，与请求无关；
- 只累计基础设施类失败：异常、超时、连接/资源类错误（含消息特征兜底识别）；
- 业务失败（参数错误、SQL 语法错、子 agent 业务失败）只上报指标与日志，**不计入熔断**，避免用户连续写错 SQL 把工具打成不可用；
- 半开态用 `acquire_slot` 占探测名额，取消/无结果时 `release_slot` 归还；
- 启动预热：`async_before_start` 为全部已注册工具建熔断器，`/metrics` 可直接观测 `codegenx_tool_circuit_state{tool_name}`。

### 前端感知（SSE 事件）

工具生命周期由执行器直接发布到 message_bus，不依赖 agent 循环：

| 事件 | 时机 | 关键字段 |
|---|---|---|
| `TOOL_EXECUTION_START` | 通过守卫与熔断准入、即将执行 | `tool_name` / `tool_id` / `arguments` |
| `TOOL_EXECUTION_END` | 所有结束路径（成功、失败、守卫阻断、熔断打开、工具不存在） | `tool_name` / `tool_id` / `success` / `state` / `error_class` / `message` |

- 载荷由 `MessageBus._sanitize_event_data` 原地标准化：补 `tool_name` / `tool_id` / `description`，保留 `success` / `error_class` 等业务字段；
- `dispatch_agent` 走同一链路（`tool_name="dispatch_agent"`），前端据此展示子 agent 派发的开始与结束；
- 子 agent 内部工具各自独立发事件，嵌套并行时前端能看到多层工具同时 running；
- 事件发布失败只记日志，不影响工具执行。
