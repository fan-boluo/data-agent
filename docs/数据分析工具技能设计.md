# 数据分析 Tool 设计

> 版本：v2.0 · 2026-11-02
> 相关代码：`backend/src/codegenx/ai_service/tools/`

---

## 核心设计原则

**只做生成不做执行** — Tool 层负责读取元数据和采样，Skill 层负责指导模型生成分析代码。

**架构分层**：
- Tool 是 LLM 的入口，负责参数校验、调用 Manager、格式化结果
- Manager 是实际干活的（MySQL 只读查询、CSV 文件读取、统计计算）
- 执行型 Agent（data_explore / csv_explore / leader）通过 function-calling 使用工具

---

## 注册机制

`ToolRegistry` 在系统启动时**扫描 tools/ 目录，自动注册所有继承 `BaseTool(ABC)` 的类**

### 工具白名单（config.json 控制）

每个 agent 的 `tools` 白名单决定它能用哪些工具。leader 默认全量可用；子智能体按职责裁剪。

### 可配置排除

config.json 的 `tools.excluded` 可配置排除特定工具名，注册时即过滤掉。

## BaseTool 基类

```python
class BaseTool(ABC):
    # 必须声明的属性
    name: str              # 工具名（function-calling 用）
    label: str             # 展示名
    description: str       # 功能描述（LLM 理解用途）
    parameters: dict       # JSON Schema 参数定义（function-calling 用）
    obs_category: str = "tool"  # 观测分类（监控用）

    async def execute(self, **kwargs) -> ToolResult:
        """工具执行入口，子类实现。"""
        ...
```

### 工具执行流程

```
LLM 输出 tool_calls
  │
  ▼
ToolExecutor.execute(tool_name, arguments)
  ├─ 查 ToolRegistry → Tool(name, executor=tool_instance.execute)
  ├─ 调用 tool_instance.execute(**arguments)
  ├─ BEFORE_TOOL_CALL hook（safe_path_guard / file_tool_param_guard / sql_trace_start）
  ├─ 执行 executor（可能抛异常 → ToolResult(success=False)）
  ├─ AFTER_TOOL_CALL hook（persist_tool_log / tool_semantics_recorder / sql_trace_end）
  └─ 返回 ToolResult（success=True/False, data/message）
```

## Manager 设计

### PostgresManager（data_explore 实际使用）

- **数据库连接管理**：从应用配置获取连接信息
- **只读查询**：禁止写操作（INSERT / UPDATE / DELETE / DROP / ALTER / TRUNCATE）
- **SQL 注入防护**：参数化查询
- **大表保护**：统计类查询加 `MAX_EXECUTION_TIME` hint；所有聚合查询默认加 LIMIT

### CsvManager

- **文件安全**：限定在配置的 `data_dir` 安全路径内，路径越界拒绝
- **自动编码检测**（chardet）
- **大文件保护**：> 500MB 强制采样（按文件大小比例跳过随机偏移后顺序读块）
- **行数估算**：大文件用文件大小 ÷ 前 1000 行平均行长估算

### StatsEngine（统计计算公共逻辑）

- `compute_numeric_stats`：均值/方差/分位数（支持采样模式）
- `compute_categorical_stats`：频率统计，去重超 max_distinct 截断
- `compute_correlation`：相关性矩阵，数值列超限时取前 N 列
- **统一采样策略**：< 10万全量 → 10-50万 10% → 50-200万 5% → > 200万 1%；采样结果标 `~` 前缀 + `≈估算值`

## 大表 / 宽表处理策略

### CSV 大文件应对

| 场景 | 判定 | 触发动作 |
|---|---|---|
| 大文件 | > 50MB 或行数 > 50万 | 自动降级采样（50万→30%, 200万→10%） |
| 宽表 | 列数 > 50 | 自动剪裁到 30 列（数值→时间→低基数优先） |
| 超大文件 | > 500MB | 强制采样（500MB→20%, 1GB→10%, >2GB→5%） |

降级时在返回结果首行标注：
```
[采样率 10%，全量约 2300 万行] [已跳过 17 列: col_a, col_b, ...]
```

### PostgreSQL 查询应对

| 场景 | 处理 |
|---|---|
| 大表行数 | 统计查询自动加 LIMIT + MAX_EXECUTION_TIME |
| 时间范围 | 必须明确起止日期占位符 |
| 聚合安全 | 除零保护（NULLIF / COALESCE） |

## 关键设计约定

1. **工具是只读入口** — 数据探索工具只查询、不修改；写操作由文件操作工具（write_file / edit_file）完成
2. **结果截断** — ToolExecutor 统一 `MAX_TOOL_RESULT_CHARS=8000` 截断，避免大表撑爆上下文
3. **参数校验前置** — BaseTool.validate_params 在 execute 之前校验必填参数
4. **Hook 守卫** — 路径安全（safe_path_guard）+ 文件参数（file_tool_param_guard）在 BEFORE_TOOL_CALL 拦截
5. **dispatched 不继承 BaseTool** — dispatch_agent 虽然叫"工具"，其实是特殊的 agent-as-tool 执行器，继承 BaseTool 但内部走特殊路径
